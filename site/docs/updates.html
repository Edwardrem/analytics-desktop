Updates

Analytics Desktop updates itself from this project’s GitHub Releases. Every update is checked against the project’s own Ed25519 signature before anything from it runs.

How it checks

  • The app checks a minute after it opens, then once a day. Turn this off with Check for updates automatically in Settings ▸ Updates. It is on by default.
  • Help ▸ Check for Updates…, or Check Now in Settings ▸ Updates, checks right away.
  • Beta releases are offered only if you turn on Include beta releases in Settings ▸ Updates. It is off by default.
  • A check is one request to GitHub’s public releases API. It carries no account, identifier or usage data; GitHub sees only what any web request shows, such as your IP address.

What's New

When a newer version is available, a window titled What's New in Analytics Desktop shows its release notes, and the notes of every version you skipped. Choose Install and Relaunch, Remind Me Later or Skip This Version. The window opens again after an update installs, and any time from Help ▸ What's New.

How an update is verified

Releases are ad-hoc signed, not signed with an Apple Developer ID, so macOS can’t vouch for who made them. The app does that check itself:

  1. It downloads the release zip, AnalyticsDesktop-<version>.zip, and its .sig signature file from GitHub over HTTPS. Only api.github.com, github.com, objects.githubusercontent.com and release-assets.githubusercontent.com are contacted.
  2. It verifies the Ed25519 signature over the zip’s exact bytes with the public key built into the app. The matching private key is held by the project owner and used only to sign releases. If the signature is missing, truncated or wrong, the update is refused.
  3. Only then does it unzip the app into a staging folder and check that it has the right bundle identifier, a newer version number and a complete app structure.
  4. It quits, swaps the new app into place, keeping the old one until the new one has launched, and relaunches.

Nothing from a download is run or opened before its signature has been verified. Files the app downloads itself aren’t marked as quarantined, which is why you don’t see the first-open warning again after an update.

If the folder that holds the app isn’t writable by you, the update can’t install and the app says so. Move Analytics Desktop into your Applications folder, or download the new version from the Releases page.

Checking a download yourself

Each release also has a latest.json file that lists every asset with its size and SHA-256 checksum. To compare a zip you downloaded by hand, run:

shasum -a 256 ~/Downloads/AnalyticsDesktop-<version>.zip
