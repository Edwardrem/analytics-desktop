Microsoft account

A Microsoft account is optional. You need a work or school account to open and save files in OneDrive and SharePoint, browse the OneLake catalog, publish to the Power BI service, apply sensitivity labels, and connect to the Microsoft cloud data sources: SharePoint, Dataverse, Azure, Fabric and Power BI semantic models. It is also one way to sign in to Azure SQL, Azure Synapse, Fabric warehouses and Azure Database for PostgreSQL and MySQL.

These features have so far been tested only against local stand-in servers, not against live Microsoft services. Please report anything that doesn’t work on GitHub.

Signing in

  1. Choose Sign In with Microsoft… from the account button in the toolbar, or open Settings ▸ Microsoft account and choose Sign In….
  2. Choose Continue in Browser. Your browser opens Microsoft’s own sign-in page, at login.microsoftonline.com for the global cloud. Analytics Desktop never sees your password.
  3. Pick your work or school account. The first time, Microsoft shows a Permissions requested page that lists what Analytics Desktop asks for. Review it and choose Accept.
  4. The browser tells you that you can close the tab, and the app shows your name and account.

If the browser can’t return to the app, choose Use a Code Instead. You then enter a short code at Microsoft’s device login page, on any device.

By default the app accepts any work or school account (the organizations authority). Settings ▸ Microsoft account can limit it to one tenant, or switch to the US Government or China cloud. Data sources sign in with a Microsoft account only in the global cloud.

What the app asks for

Permissions are delegated: the app acts as you, and can reach only what your account can already reach. Each service gets its own token. Signing in asks only for the Microsoft Graph permissions. The others are asked for the first time you use a feature or data source that needs them, and then Microsoft may ask you once more to consent to just that service.

  • Microsoft Graph, at sign-in:
    • User.Read: your name and photo for the account button.
    • Files.ReadWrite.All: open and save reports in OneDrive and SharePoint, and read OneDrive and SharePoint files as data.
    • Sites.Read.All: browse SharePoint sites, libraries and lists.
    • offline_access, openid, profile: stay signed in between launches, and know who you are.
  • Power BI Service: workspaces, semantic models and reports, for Publish, the OneLake catalog and the Power BI semantic models connector.
  • Microsoft Fabric: workspace items and OneLake, for the OneLake catalog.
  • Microsoft Graph InformationProtectionPolicy.Read: the sensitivity labels you can apply.
  • Data sources, each as user_impersonation: Azure SQL Database (SQL Server family), Azure Storage (Blob, Data Lake Storage Gen2 and OneLake), Dynamics CRM (Dataverse), Azure Data Explorer, and Azure OSSRDBMS Database (Azure Database for PostgreSQL and MySQL). SharePoint AllSites.Read covers SharePoint addresses read with the Web connector.

Where your sign-in is kept

The refresh token is stored only in the macOS Keychain. Each token is bound to the service it was issued for, and the app checks the host before it sends one. A Graph token goes only to graph.microsoft.com and a Power BI token only to api.powerbi.com. A SQL token goes only to Azure SQL, Synapse and Fabric SQL hosts, and a Storage token only to storage accounts and OneLake. A Dataverse, Data Explorer or SharePoint token goes only to that environment’s, cluster’s or tenant’s own address. If a request names any other host, nothing is sent and the app says why.

Sign Out in Settings ▸ Microsoft account removes the account and its refresh token from the Keychain. Passwords, keys and other data source credentials are kept in the Keychain too. You manage those in Data source settings; see Credentials.

For organisations: admin consent

Many organisations don’t let people approve apps on their own. If yours doesn’t, Microsoft shows Need admin approval instead of the permissions page, and may offer to send a request to your admin. Nothing is wrong with the app: an administrator has to approve it once for the whole organisation.

An administrator (Cloud Application Administrator, Application Administrator or Global Administrator) can do that in one of two ways:

  • In the Microsoft Entra admin center. After someone in the organisation has tried to sign in, open Enterprise applications, find Analytics Desktop, open Permissions and choose Grant admin consent for your organisation.
  • With an admin consent link. Open this link while signed in as an administrator, replacing <tenant> with your tenant ID or domain: 
    https://login.microsoftonline.com/<tenant>/adminconsent?client_id={CLIENT_ID}
    This link is for the app’s own registration. If your organisation uses its own registration, use that registration’s application ID instead.

Admins can also review the requested permissions, and revoke them at any time, from the same Enterprise applications page.

Using your own app registration

Analytics Desktop signs in with its own multi-tenant app registration, so normally there is nothing to set up. Its application ID is built into the app and isn’t shown in Settings: when it is in use, the Application (client) ID field in Settings ▸ Microsoft account is empty and shows the placeholder “The app's own registration”.

If a copy of the app has no application ID built in, it says so: this copy has no Microsoft application ID, so get a build with one or enter your organisation’s own. Sign In with Microsoft… then opens Set up Microsoft sign-in to ask for an application ID first, and the Sign In buttons in Settings and in Get Data stay disabled until one is saved.

To use a registration your organisation controls:

  1. In the Microsoft Entra admin center, register a new application that accepts accounts in any organizational directory. Add the platform Mobile and desktop applications with the redirect URI http://localhost, and turn on Allow public client flows (needed for device-code sign-in).
  2. Add the delegated permissions listed above for the features you use.
  3. In Settings ▸ Microsoft account, enter its application (client) ID and, if you like, your tenant, then choose Save Registration and sign in. To go back to the app’s own registration, empty the field and save again.

How to Register… in Settings ▸ Microsoft account shows the same steps, with buttons to open the Entra admin center and copy the redirect URI. No client secret is needed or used: the app signs in as a public client with PKCE.
