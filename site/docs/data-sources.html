Data sources

Choose Get Data on the Home tab of the ribbon. The list has every connector Power BI Desktop offers. Those the app can read are listed normally. Those it can’t are dimmed, show the reason, and can’t be started.

The database and Microsoft cloud connectors are new in this beta. The cloud connectors have been tested only against local stand-in servers. SQL Server has been tested only against a stand-in server, and MySQL and MariaDB have never run against a real server. Please report problems on GitHub.

What works, with limits

Databases

The app talks to these servers with its own protocol clients, so you don’t install a driver. Each one offers Import or DirectQuery, folds Power Query steps into SQL, and runs a SQL statement you type only after you approve it.

These need a work or school Microsoft account. The first time you use one, Microsoft may ask you to consent to that service.

Parquet

Parquet files with a flat schema load from a file or a folder. Nested groups become dotted column names, and repeated columns aren’t supported. Pages must be uncompressed or compressed with Snappy or gzip.

Credentials

Sign-in methods are Anonymous, Basic (user name and password), Web API (a key sent in a header or query parameter), Organizational account, and, for Azure Storage, Account key and Shared access signature (SAS). Which ones are offered depends on the source.

  • Credentials are kept in the macOS Keychain, one item per source. They are never written into your documents or shown again.
  • To add or change them, open Data source settings, select the source and choose Edit Permissions…. Clear Permissions forgets them.
  • When a source refuses during Get Data, the app asks for credentials and then tries again. During a refresh or in the Power Query Editor, the error names the source instead, and you edit it in Data source settings.
  • An organizational account’s token is sent only to the Microsoft service it was issued for, at the addresses the app allows for that service. Data source sign-in with a Microsoft account works only in the global Microsoft cloud.

What isn’t available

These are listed but dimmed, with the reason in their tooltip. Typing one of their M functions fails with a message that it isn’t available.

  • Databases that need a vendor driver: Oracle, IBM Db2, Teradata, SAP HANA and BW, Snowflake, Google BigQuery, Databricks, Analysis Services and others. Also ODBC, and the Windows-only Access, OLE DB and Active Directory.
  • PDF, and the binary Excel formats .xls and .xlsb (save as .xlsx).
  • Fabric dataflows, datamarts, SQL databases, mirrored databases and KQL databases, and Power Platform dataflows.
  • Azure Analysis Services, Table Storage, Cosmos DB, HDInsight, Databricks, Cost Management and Resource Graph.
  • Online services such as Salesforce, Google Analytics, Adobe Analytics, GitHub, Exchange, Outlook Mail and Business Central, and on-premises SharePoint lists.
  • SharePoint folder navigation (SharePoint.Contents), and custom .mez and .pqx connectors.

Import and DirectQuery

  • Import is the default. The rows are saved in your .facet file.
  • DirectQuery works for SQLite and the database servers above. Rows aren’t saved in the file. The folded table is read on load and on refresh, up to 1,000,000 rows, and visuals are computed on your Mac, so it isn’t one SQL query per visual.
  • Dual can be chosen, and behaves as Import.

Refresh

Home ▸ Refresh reloads every table. You can also refresh one table, refresh only the visuals, or refresh the preview inside the Power Query Editor. Automatic page refresh re-queries a page at an interval while the window is open.

Privacy levels and native queries

  • Each source can be given a privacy level (Private, Organizational or Public) in Data source settings. The query engine then refuses to combine data in a way that could send private data to another source, unless you choose to ignore privacy levels in Settings ▸ Security.
  • A SQL statement, Azure Data Explorer query or DAX query you type runs only after you approve it. Approvals are remembered per source until you clear them in Data source settings.
